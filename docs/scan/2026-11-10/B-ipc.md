# B-ipc — PhantomVault trust boundary audit (page ↔ extension ↔ Rust)

Scope: `src/windows_native/native_host.rs`, `src/api/{local,token}.rs`, `browser_extension/{manifest.json,manifest.firefox.json,background.js,content.js,popup.js,hook.js,offscreen.js,domain.js}`.
Read-only audit. No repo files modified.
Version audited: 0.4.1.

Severity model: **P0** = a web page reaches vault secrets with no user action; **P1** = a page/extension-origin bypass that leaks secrets or defeats 2FA; **P2** = hardening / defence-in-depth.

## Verified good (checked, no finding)

- **Framing / memory DoS** — `native_host.rs:148-160`: 4-byte LE length, `read_exact`, `len == 0 || len > MAX_MSG_BYTES` rejected **before** `vec![0u8; len]`; 1 MiB cap matches Chrome's. Truncated body, garbage JSON and oversize prefix all rejected, covered by `framing_roundtrip_and_cap` (`:3828-3844`). No unbounded read.
- **Per-frame unlock gating** — every secret-bearing command re-checks `unlocked` (`query:571`, `fetch:1546`, `list:1383`, `totp_lookup:1122`, `cards:641`, `identities:688`, `stats:1733`, `assert:739`, `attest:997`, …). The serve loop re-derives it each iteration (`:3699`) and exits on token deletion (`:3557`), 60 s idle, or 8 h. Decoy sessions refuse every persisting command (`:3600-3615`) and are refused in the API.
- **Shutdown / EOF** — `frame read` error ⇒ clean break (`:3585-3588`); clipboard timer keeps the process alive only until `ttl+2 s` (`:3740-3760`); no `unwrap()` on the protocol path.
- **Local API surface** — binds `127.0.0.1:0` (loopback + random port) at `local.rs:141`; token 32 random bytes, DPAPI-sealed, 24 h expiry, revoked on disable; `Authorization: Bearer` **header only** (never query string, `:240-250`); constant-time compare; 16 KiB request cap + 5 s read/write timeouts (`:184-190`); 30 req/min; per-request UI Allow/Deny with audit log; off by default; refused in decoy.
- **hook.js is data-free** — runs in the MAIN world but only posts key-name tripwires (`bodyLooksLikeLogin` / `…Card` / `…Identifier`); values are re-read from the DOM by the content script (`content.js:4163-4170`). A hostile page hooking `window.postMessage` learns only "a login form posted", never a credential. The `PV_WEBAUTHN_FULFILL` reply channel lets a page resolve its own promise — no privilege gain, it already owns its own JS context.
- **No XSS** — every `innerHTML` in `content.js` (563, 608, 644, 759, 784, 1961, 1990, 2031, 2545) and `popup.js:1990` is a static template or a `PV_ICO[...]` constant; vault-derived strings go through `textContent` (`content.js:615-617`, `popup.js:1999-2001`). No `insertAdjacentHTML`/`outerHTML`/`document.write`. The leak here is the open shadow roots / page-DOM hosts, not injection.
- **No remote/eval code** — no `eval`, no `new Function`, no remote `<script>`; `importScripts("domain.js")` is local; `popup.html` loads only `domain.js` + `popup.js`; no `content_security_policy` override ⇒ MV3 default CSP applies.
- **No `externally_connectable`** in either manifest ⇒ a web page cannot `chrome.runtime.sendMessage` the extension at all; B4 is reachable only from extension contexts (content scripts), which is why B1/B2 matter so much.
- **Save-path sender checks** — `background.js:717-729` files saves under the **sender frame's** registrable domain, not the tab's (P6), so a cross-origin login iframe cannot be filed under the top site; `never_save` honoured.
- **Popup-only mutations** — create/update/delete, reprompt and native copy are rejected when `sender.tab` exists (`:599`, `:612`), and armed rows require a single-use master-reprompt token.
- **Clipboard auto-clear** — `offscreen.js` only ever sees a SHA-256 hash; mismatch ⇒ no-op. Native `copy_secret` sets the Win+V/cloud exclusion formats with a 5–120 s TTL and flushes on lock.
